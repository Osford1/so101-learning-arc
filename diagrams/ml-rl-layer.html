Where a typed-decision service plugs into the ML/RL layer

SO-101 gummy-bear pipeline: teleop data in, policies trained, rollouts scored. The decision service enters as a typed-decision step, not as the model that drives anything.

The focal hook

Episode QC gate

Sits between recording and lerobot-train. Per episode it sends structured telemetry - start pose vs fixed_reset_joint_positions, joint-trace jerk, gripper state, the success flag - plus three typed questions, and gets back keep / relabel / discard with a probability each.

  • Attacks the known failure: 30 episodes whose resets drifted, producing erratic motion.
  • Cost is irrelevant at this volume - a whole dataset is cents.

Why this shape

Judgment, not text

Both hooks ask a question whose answer set you can name in advance, which is exactly a typed-decision service's shape. Deterministic code still owns the pipeline; the service supplies the label and a probability you threshold yourself.

  • Independent tests found the confidence is honest near 0 and 1 and a coin flip in the middle - fit your own cut-offs.
  • The service is text and structured data only. The vision reward classifier stays in LeRobot.

Deliberately cut

HIL-SERL supervisor

A third hook that decides intervene / continue / abort during RL rollouts belongs in this layer, but not in this diagram.

  • At 70-500 ms per call it fits a 1-2 Hz supervisor loop, not a 30 Hz control loop.
  • Add it at Phase 8, once the arm is attached and teleop is stable.
